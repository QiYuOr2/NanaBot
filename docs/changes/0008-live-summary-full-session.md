# 0008 直播摘要覆盖整场弹幕

- **状态**：已完成
- **日期**：2026-11-12
- **影响范围**：`packages/live-summary`
- **关联需求**：反馈直播摘要只读取最后一段时间的弹幕，而不是整场。
- **关联条目**：[上一条](./0007-bot-file-logs.md) · [返回概览](./README.md)

## 背景

`buildDanmuExcerpt` 原来用 `usable.slice(-160)` 取最后 160 条弹幕，再把这 160 条交给模型。
短场次看不出问题，但一场直播累计几千条弹幕时，160 条通常只覆盖下播前几分钟；
开播和中段观众讨论的内容被完整丢弃。高频弹幕虽然按全量统计，但摘要主体仍然严重偏后。

单场弹幕量通常在 5000 条以内，完整正文大多能放进 DeepSeek 上下文；原先 7000 字符的摘录上限过于保守。

## 变更内容

| 文件                                          | 类型 | 说明                                                                     |
| --------------------------------------------- | ---- | ------------------------------------------------------------------------ |
| `packages/live-summary/src/excerpt.ts`        | 修改 | 5000 条以内且不超过 64k 字符时直接使用完整弹幕；超量时退回全程等距抽样。 |
| `packages/live-summary/src/prompt.ts`         | 修改 | 提示词区分「完整弹幕」和「等距样本」，避免模型误判相邻行是否连续。       |
| `packages/live-summary/src/deepseek.ts`       | 修改 | 完整弹幕的输入更长，请求超时从 45 秒放宽到 90 秒。                       |
| `packages/live-summary/tests/summary.test.ts` | 修改 | 覆盖 5000 条全量、超量抽样、超长字符上限和提示词分支。                   |

## 关键决策与取舍

- **优先全量，超量才抽样**：5000 条左右是已知上限，完整正文可以覆盖绝大多数场次；只有超过 5000 条或 64k 字符时才启用等距抽样兜底。
- **按消息条数等距抽样，而不是按时间桶**：`SummaryMessage` 只有正文，存储层已按 `sent_at` 排序；按条数采样无需改动接口，也能保证整场首尾都进入样本。
- **抽样字符超限时减少样本条数，而不是从字符串尾部截断**：尾部截断会再次退化成「只看最后一段」，与新目标冲突。
- **保留全量高频弹幕统计**：重复句统计本来就遍历整场，继续保留，用来补充抽样可能漏掉的集中话题。

## 兼容性与数据安全

- 数据库结构、存储接口和页面接口均未变化，无需迁移。
- 已经生成过的摘要仍是 `ok` 状态，不会自动重新调用模型；需要重新生成时要先清掉该场次的摘要字段。
- 原始弹幕仍完整保留在 `danmu_message`，本次只改变送进模型的摘录方式。

# 0013 低内存部署选项

- **状态**：已完成
- **日期**：2026-11-12
- **影响范围**：部署脚本与文档
- **关联需求**：1.8 GiB 内存的服务器在 `pnpm app deploy site` 构建 Nitro 阶段被 OOM killer 杀掉。
- **关联条目**：[上一条](./0012-site-tests-via-bot-control.md) · [返回概览](./README.md)

## 背景

`pnpm app deploy` 默认保留旧应用进程运行，等构建成功后再执行 `pm2 startOrRestart`。
这样可以避免构建失败导致服务下线，但在小内存机器上，旧 bot、旧 site 与 Nuxt/Nitro 构建进程
会同时占用内存，容易触发全局 OOM。

## 变更内容

| 文件                  | 类型 | 说明                                                                  |
| --------------------- | ---- | --------------------------------------------------------------------- |
| `scripts/app.mjs`     | 修改 | 新增 `deploy --stop-before-build`，构建前停止选中应用；失败时尝试恢复 |
| `README.md`           | 修改 | 补充低内存部署命令                                                    |
| `apps/site/README.md` | 修改 | 补充 site 的部署说明                                                  |

## 关键决策与取舍

- 做成显式选项而不是默认行为：`deploy all` 默认仍保持旧服务在线，避免普通部署产生额外停机。
- 仅在实际执行构建时停止应用；与 `--no-build` 同时使用时不会触发停止或恢复。
- 构建失败后执行 `pm2 start` 恢复原应用，再以原构建退出码结束。
- 构建失败时 `.output` / `dist` 可能已经被部分写入；恢复动作只保证尽力拉起原进程，
  不保证失败构建留下的产物一定可运行。

## 兼容性与数据安全

- 不改变现有 `deploy` 默认行为，不改变应用配置或数据结构。
- 停止与恢复都只针对本次选中的应用，不影响其他 PM2 应用。

## 验证

| 验证                   | 命令 / 方式                                          | 结果 |
| ---------------------- | ---------------------------------------------------- | ---- |
| 格式化、lint、类型检查 | `pnpm exec vp check`                                 | 通过 |
| CLI 参数解析           | `pnpm app deploy site --stop-before-build --dry-run` | 通过 |
| 构建失败恢复流程       | 使用临时 `vp` / `pm2` shim 模拟构建失败              | 通过 |

## 未决事项 / 后续可选项

- 如需在构建失败时保证运行旧产物，可进一步改成先构建到临时目录、成功后原子替换。

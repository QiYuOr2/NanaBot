# 0002 推送活动独立页面 `/pushes`

- **状态**：已完成
- **日期**：2026-09-15
- **影响范围**：`apps/site`（新增页面与列表项组件、侧边栏导航、面板卡片入口）
- **关联需求**：面板页的推送活动最多 5 条，点击「查看全部」跳转到独立的推送活动页面
- **关联条目**：[上一条 0001](./0001-push-activity-aggregation.md) · [下一条 0003](./0003-layout-and-header.md) · [返回概览](./README.md)

## 背景

改动前「查看全部」只是 `PushLogCard` 内部的 `expanded` 开关，最多把接口返回的 20 条原始记录就地展开，既没有真正意义上的「全部」，也让面板卡片承载了两种视图。

配合 [0001](./0001-push-activity-aggregation.md) 的合并结果，需要一个新的页面来展示全部活动，并且能看到每个群的送达明细（原始数据不丢的可视化出口）。

| 文件                                            | 类型 | 说明                                                                                                                                          |
| ----------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/site/app/pages/pushes.vue`                | 新增 | `/pushes` 页面：面包屑「NanaBot / 推送活动」、刷新、统计行（活动数 / 原始记录数）、全部活动列表、截断提示、空态。                             |

## 复用策略

独立页面没有新增任何数据获取或合并逻辑，三处复用：

1. **接口**：与面板同一个 `GET /api/push-log`（`useFetch`），SSR 时直接取数渲染；
2. **合并逻辑**：`buildPushActivities` 只在服务端跑一次，两个页面消费同一份 `activities`；
3. **展示组件**：`PushActivityItem` 被面板卡片和独立页面共用，面板只渲染最新 5 条、不传 `show-targets`。

## 组件契约

`PushActivityItem`：

| 属性          | 类型           | 默认值  | 说明                                     |
| ------------- | -------------- | ------- | ---------------------------------------- |
| `activity`    | `PushActivity` | 必填    | 一条合并后的活动                         |
| `last`        | `boolean`      | `false` | 是否是时间轴最后一条，用于隐藏连线       |
| `showTargets` | `boolean`      | `false` | 是否展开每个群的送达明细（独立页面开启） |

`PushLogCard`：

| 属性    | 类型             | 默认值                           | 说明             |
| ------- | ---------------- | -------------------------------- | ---------------- |
| `items` | `PushActivity[]` | 必填                             | 合并后的活动列表 |
| `limit` | `number`         | `PUSH_ACTIVITY_PANEL_LIMIT`（5） | 最多渲染几条     |

## 页面行为细节

- 统计行：「同一主播同一次直播的推送已合并，共 N 条活动 · M 条原始记录」；
- 每个活动下方的群明细逐条列出 `群昵称 + 已送达 / 失败`，失败项 `title` 展示原始错误信息；
- 接口返回 `truncated` 时页面提示「仅展示最近 N 条原始推送，更早的活动未加载」，与 [0001](./0001-push-activity-aggregation.md#接口契约) 的窗口语义对应；
- 无数据时显示「暂无推送记录。」，加载失败时显示错误卡片。

## 未决事项 / 后续可选项

- 独立页面当前展示的是「窗口内全部活动」（最多 500 条原始记录对应的量），没有分页；数据量上来后需要游标分页，那时 `readPushLogs` 也要加 offset / 游标能力。
- 页面暂无按主播 / 目的筛选，需要时优先加在服务端 query（与 `rawLimit` 同一层），避免在客户端做二次过滤。

# 0017 Site 日志标签化与最新日志定位

- **状态**：已完成
- **日期**：2026-11-12
- **影响范围**：`apps/site`
- **关联需求**：日志页的时间戳 / log level / from 三段样式都 tag 化；进入日志页面、切换日志文件都定位到最新的一条，不要显示最开始的。
- **关联条目**：[上一条](./0016-site-deploy-target.md) · [返回概览](./README.md)

## 背景

`/logs` 原先使用单个 `<pre>` 直接输出文件末尾内容，所有字段共用同样的文字颜色，排查时难以快速区分日志等级与账号来源；加载后滚动位置停在顶部，而接口返回的是按时间正序排列的末尾若干行，用户首先看到反而是本段日志里较早的内容。

## 关键决策与取舍

- bot 的 `formatLine` 格式为 `[YYYY/MM/DD HH:mm:ss] [LEVEL] [scope] message`，解析放在 `shared/` 纯函数，既不改变日志文件，也不改变 `/api/logs` 响应结构。
- 时间戳统一使用固定底色；`DEBUG / INFO / WARN / ERROR` 分别使用不同底色，别名（如 `TRACE`、`WARNING`、`FATAL`）与未知等级也有稳定配色。
- `from` 按来源文本首次出现顺序分配八种底色，同名来源在同一段日志内始终同色；来源过长时截断展示，悬停可看完整值。
- 错误堆栈与普通前缀文本不匹配结构化格式时按续行原样渲染，避免丢失原始日志信息。
- 滚动定位使用日志容器的 `scrollTop = scrollHeight`，并在 `nextTick` 与下一帧各执行一次，覆盖首次 SSR 水合、切换文件和手动刷新后的 DOM 高度变化。
- 标签配色来自共享模块中的字符串，UnoCSS 无法从模板直接提取这些动态类，因此在 `uno.config.ts` 用 safelist 固定所需类，而不是把配色散落到组件里。

## 兼容性与数据安全

- 接口、日志文件格式、bot 写入逻辑、鉴权与日志读取路径均未变化。
- 原始文本仍按行完整展示；只是把三段元信息从纯文本拆成标签，错误堆栈的缩进也保留。
- 超过 8 种来源后颜色会循环复用；颜色只用于辅助区分，文本仍显示完整来源名。

## 未决事项 / 后续可选项

- 颜色按来源文本在单次加载内容内分配；切换文件后同一来源仍会使用相同的第一组颜色规则，但不保证不同文件中来源集合顺序变化时颜色完全一致。若需要跨文件持久化，可改为对来源字符串做稳定哈希。

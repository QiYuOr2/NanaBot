# 0010 site QQ 群测试消息

- **状态**：已完成

- **关联需求**：在已配置 group_openid 的群上提供普通消息与 @全体测试按钮。
- **关联条目**：[上一条](./0009-mixed-qq-accounts.md) · [返回概览](./README.md)

## 变更内容

设置页的群映射保存成功后显示「测试普通消息」与「测试 @全体」按钮。有未保存修改或正在发送时禁用按钮，发送后显示结果。@全体按钮说明管理员权限和每日额度，测试也消耗额度。

`POST /api/settings/qq-groups/test` 沿用配置管理口令，校验官方账号、已保存群映射和页面预期 openid。请求只能选择账号、群别名与消息类型，目标和固定正文由服务器决定；映射已变化时返回冲突，不发送到新目标。

服务端复用 `@nana/qq`，从进程环境或 `apps/bot/.env` 读取该账号引用的凭据，仅发送 HTTP 请求，不建立 Gateway 连接。成功需返回官方消息 ID；权限、额度及其他发送错误显示失败，不取消 @全体后重试。响应和日志中的错误隐藏机器人密钥。

每次发送尝试写入 `message.test` 推送记录，显示名「测试消息」，包含账号、群和成功 / 失败状态。验证不通过的请求不发送、不记录为发送尝试。发送成功后若记录失败，只输出服务端日志，不重复发群消息。

环境变量读取收口为 `@nana/utils.readAppEnvValue`，配置管理口令、DeepSeek 摘要和 QQ 测试共同使用，支持标准 .env 引号及注释，不改写进程环境。

## 验证

- `vp check`、`vp test` 与 bot / site 生产构建。
- HTTP 回归覆盖鉴权、未映射群、账号隔离、凭据选择、目标变更、任意目标拒绝、@全体编码、失败不重发、失败记录和密钥隐藏。
- 浏览器覆盖未绑定时隐藏、保存后出现、未保存修改禁用、两种发送反馈、失败提示、发送中禁用以及移动端布局。
- 所有验证使用隔离配置和模拟的 QQ 请求，不向真实 QQ 群发送测试消息。
